# 客服交接摘要与未决事项研究

客服换人接手时，给下一位客服看的摘要，会不会漏掉用户还没解决的问题？这个项目先从 CSDS 对话中筛出售后候选，在中途模拟交接，再由人工判断当时有哪些事情没办完。

程序目前支持筛选、抽样、保存人工检查材料，以及根据人工标注导出模型输入和参考答案。A/B 摘要生成、摘要评分和统计分析还需要另做。关键词命中不代表确实存在未决事项，候选数量也不能用来证明摘要效果。

## 第一次使用

需要 Python 3.10 或以上，无第三方 Python 依赖。先按 [数据说明](02_数据/README.md) 准备 `02_数据/原始数据/train.json`，然后在项目根目录运行：

```powershell
python .\csds_screen.py screen
```

Windows PowerShell 也可用：

```powershell
.\运行项目.ps1 -Action screen
```

默认抽30段，随机种子为20261023。每次结果放在 `04_实验记录` 下的新目录中，不覆盖已有结果。阅读其中的 `review_batch.md`，再按 [标注方法](05_人工标注/标注怎么填.md) 建立参考答案。具体命令见 [运行说明](03_程序/运行说明.md)。

不准备真实数据，也能先检查程序：

```powershell
python -m unittest discover -s .\03_程序 -p "test_*.py" -v
```

测试使用代码生成的示例，不需要真实客服对话。

## GitHub 仓库包含什么？

当前 `.gitignore` 只放行程序、规则和通用说明。原始 CSDS 数据、对话片段、人工标注、运行日志、历史备份和本地状态页都保留在本机。下载仓库的人需要自行准备数据，再运行生成自己的记录。

把代码传到 GitHub 不等于备份了整个实验。原始数据、标注和实验记录仍需另行备份；数据使用和分享要遵守原数据许可。本仓库尚未指定代码开源许可证。

第一次上传请看 [Git 与 GitHub 入门](Git与GitHub入门.md)。以后新增要共享的文件，也要检查它是否被 `.gitignore` 排除；规则修改应另存版本并说明理由。
